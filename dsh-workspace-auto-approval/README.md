# dsh-workspace-auto-approval

DSH 插件：**工作区自动审核**。

它向 DSH 权限选择器新增第四种 **“工作区自动审核”** 模式。该模式在
`danger-full-access + ask` 权限边界下运行：命令在完整环境中执行，不受受限沙箱对
凭据、命名管道与子进程 helper 的限制——`git push`、ssh、包管理器等依赖这些能力的
命令都能正常工作。作为交换，插件在**每个工具调用执行之前**（`tools/pre-execute`）
逐个审计：工作区内操作、白名单命中和明确的只读访问自动放行；无法由简单规则可靠
判断的命令或 MCP 调用，交给当前会话使用的 AI 做一次带工具定义、但不可调用工具的
审核；批量破坏、主机级变更与网络上传等高风险操作直接转人工审批。普通 `Workspace
Write` 模式保持原行为。

## 安装

```powershell
dsh plugin --profile web add "github:yzlin499/dsh-yzlin499-easy-plugins#path:/dsh-workspace-auto-approval"
```

重启 DSH Web 后生效。

## 使用

安装并重启后，在会话的权限选择器中选择 **“工作区自动审核”**。只有选中该模式时
插件才会介入；切回 `Workspace Write` 后，DSH 恢复原有沙箱与审批链。自动审核模式
在每个工具调用执行前按以下顺序判断：

| 情况 | 处理 |
|---|---|
| `write` / `edit` 的目标在当前工作区内 | 自动放行 |
| `pwsh` / `bash` 是明确的只读命令 | 自动放行，包括读取工作区外文件 |
| `curl` 使用简单白名单参数执行明确的网络 GET/HEAD | 自动放行 |
| 命令文本命中「自定义放行规则」的任一正则（默认已含 `git push`） | 自动放行；批量破坏类操作不受影响，仍转人工 |
| 其他无法由只读规则证明的命令或 MCP 调用 | 调用当前会话模型审核；仅回答 `ALLOW` 才放行 |
| 递归/通配批量删除、`git clean -fd`、删库/删表/清表及破坏性 MCP | 不进入 AI，直接转人工审批 |
| 命中系统服务、注册表、用户管理、关机、网络上传等高风险规则 | 直接转人工审批 |
| AI 报错、超时、无可用模型或未明确允许 | 转人工审批 |
| 「自动放行」开关已关闭 | 所有调用都转人工审批（包括只读与白名单命令） |

自动放行的调用直接执行，不放行的调用在其**执行前**被拦下转人工——插件不修改会话的
持久权限档位。

## 设置

在「设置 → 插件 → 工作区自动审核」展开设置卡片，可以编辑三块内容：

1. **审核 System Prompt**：AI 审核使用的系统提示词。支持保存和恢复默认，最多 8000
   字符；配置由官方 `ctx.settings` 持久化到 `~/.dsh/settings.yaml` 的
   `dsh-workspace-auto-approval.prompt`。
2. **自动放行开关（grantFullAccess）**：默认开启。开启后，只读、工作区内、白名单
   命中与 AI 通过的调用在审计后直接放行执行；关闭后，**每一个**工具调用都转人工
   确认（AI 审核也不再触发）。持久化到
   `dsh-workspace-auto-approval.grantFullAccess`。
3. **自定义放行规则（allowPatterns）**：每行一条正则（不区分大小写），命令文本命中
   任一规则即自动放行。**默认已含 `\bgit(?:\.exe)?\s+push\b`**，即 `git push` 不再走
   AI 审核、直接自动放行；可在此增删任意命令（如 `npm publish`）。持久化到
   `dsh-workspace-auto-approval.allowPatterns`，保存时校验正则合法性（非法正则拒绝保存）。

修改后的提示词、开关与规则从下一次调用起生效，不需要重启。高危大规模破坏规则在提示词和
自定义规则**之前**确定性执行，用户无法通过修改提示词或放行规则绕过“必须交给用户判断”
的限制。

## 工作原理

- Bundle 补丁重述官方三种权限预设，并追加 `workspace-auto-approval`。它与
  `danger-full-access` 共用 `sandbox: danger-full-access`、`approval: ask`，DSH 通过
  持久的 `permission/preset` 事件区分用户选中了哪一种。**该模式没有 OS 级文件沙箱**：
  命令在完整环境中执行，受限沙箱对命名管道/凭据的破坏不再影响 git 等命令。
- Host 插件以 `prepend` 方式监听 **`tools/pre-execute`**（DSH 工具注册表在每次分发
  **执行前**触发的 waterfall 决策点，见 `dsh-tools`），仅在当前预设为
  `workspace-auto-approval` 时介入；其他模式立即调用 `next()`。
- **执行前审计**：插件直接读取该次调用的解析参数（`exec.arguments`）运行本地规则
  分类，无需回查会话事件：
  - 只读命令 / 工作区内文件目标 / 白名单命中（含 `git push`）→ 返回 `allow`，调用
    直接以完整环境执行；
  - 批量破坏、主机级变更、网络上传 → 返回 `ask`（reason 带 `[workspace-auto-approval]`
    标记），由 DSH 审批服务弹给用户；
  - 其余 → 复用当前会话模型做一次带工具定义、不可调用工具的 AI 审核，仅回答
    `ALLOW` 才返回 `allow`，否则返回 `ask` 转人工。
- **插件失败一律关闭（fail closed）**：`tools/pre-execute` 审计抛错时返回 `deny`，
  调用被拦截，不会静默放行。
- `ask` 会经 `approval` 服务触发 `approval/request`；宿主插件的旧监听器只对带
  `[workspace-auto-approval]` 标记的 reason 直接 `next()`（交回人工），保证
  执行前审计的结论不会被二次改写或自动放行。旧监听器保留了对（该模式下理论不再
  出现的）沙箱提权申请的处理，兼容性不受影响。
- Client 半侧为该预设补充与官方一致的 16×16 “盾牌 + A” SVG 图标。官方
  `PresetOption` 没有图标字段，因此 Client 只匹配完整标签“工作区自动审核”，通过 CSS
  SVG mask 装饰当前模式按钮和菜单项；不修改官方包，卸载时自动清理。独立源文件见
  `icon.svg`。
- 工作区边界来自 `session.header.cwd`；路径比较会解析已存在的符号链接/目录连接，避免只做
  字符串前缀判断。
- Host 用官方 `ctx.settings` 注册 `dsh-workspace-auto-approval` 命名空间，设置卡片通过
  `/workspace-auto-approval/config` 读写提示词；每次 AI 审核都读取最新值。
- 本地规则优先：结构化文件目标、命令工作目录、绝对路径、父目录跳转、动态路径、只读命令、
  网络读写和常见系统级副作用分别判断。shell 写命令不会仅凭文本路径被本地规则放行，
  因为变量、通配符和可变符号链接无法由字符串检查可靠约束。
- 自定义放行规则（allowPatterns）在批量破坏检查之后、其余本地规则之前执行：命令文本命中
  即放行（含网络写、主机级变更等其它规则本会转人工的命令），但批量破坏类操作永远优先、
  无法被规则覆盖。规则按**整条命令文本**匹配（含组合命令，需谨慎编写）；非 shell 工具按
  「工具名 + 参数 JSON」匹配，`write`/`edit` 工具的工作区外目标不会被规则放行。
- AI 兜底复用当前会话最近一次请求的 provider/model，发送工作区、审计理由、匹配到的
  工具定义（名称、描述、参数 schema）和本次实际参数，JSON 输入上限为 32 KiB。这使名称
  不透明的 MCP 工具也能结合定义判断读写性质。请求仍显式设置 `tools: []`，审核模型只能
  阅读 schema，不能调用任何工具，也不携带会话历史。
- 审核请求允许推理：优先沿用当前会话已启用的 `reasoningEffort`；未启用时查询模型能力，
  自动选择第一个非关闭档位（DeepSeek 通常为 `low`）。模型不支持推理时不传该字段。
  `maxTokens: 256` 为隐藏推理预留空间，超时仍为 15 秒。
- AI 只有完整输出 `ALLOW` 才能授权；任何其他输出和异常都转人工审批。若会话审批策略是
  `never`，DSH 会按原策略拒绝转人工的请求（该模式预设为 `ask`，通常不会出现）。

## 安全边界

本模式的预设档位是 `danger-full-access`，**没有 OS 级文件沙箱**；插件规则与 AI 是
该模式下唯一防线。它只能判断命令意图，无法像操作系统沙箱一样证明任意 shell 脚本的
全部运行时副作用。因此：

- 大规模破坏、主机级变更、网络上传规则在 AI 与自定义规则**之前**确定性执行：批量删文件、
  递归强删、删库/删表/清表等不会因自定义提示词、放行规则或 AI 输出而自动授权；
- 默认白名单含 `git push`，意味着推送到**任意**远端都会被自动放行——请自行评估风险；
  规则匹配整条命令文本（组合命令会整条放行）；
- 「自动放行」开关只决定“审计通过后是否直接执行”：开启=自动放行，关闭=全部转人工确认。
  它不影响批量破坏类操作（永远转人工）；
- 本模式放弃 OS 沙箱换来命令可用性：需要凭据/子进程 helper 的命令（git、ssh、包管理器）
  能正常工作，但审计必须承担全部拦截职责。不确定时请切回官方 `Workspace Write` 或
  `read-only` 预设，保留系统级隔离；
- MCP 工具 schema、审批理由和实际参数会发送给当前会话使用的模型提供商；参数中含有敏感
  信息时，应把这视为一次对该提供商的数据披露；
- AI 不是安全边界，生产环境或无人值守环境应保留 DSH 官方沙箱预设，并按风险决定是否
  安装本插件。
