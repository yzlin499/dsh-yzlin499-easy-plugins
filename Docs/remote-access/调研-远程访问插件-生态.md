# 调研：DSH 远程访问 / 跨机器插件生态

> 日期：2026-10-28 · 纯网络调研（未改仓库任何代码、未安装任何包）
> 场景：人在家里，想让家里的 DSH 连到公司那台机器上跑的 DSH —— 远程用公司的工作区 / 会话 / Agent。

## 0. 一句话结论

**"远程连接 DSH"在 DSH 生态里不但已经存在，而且是一个有 100+ 条目的成熟品类**（awesome 列表有专门的 `Remote & Mobile` 分类，本次拉到的目录快照里该分类 127 条）。用户描述的「家里 ↔ 公司两台 DSH 互相访问会话/工作区」有**至少 4 个直接对味**的方案，其中 `dsh-ssh-workspace`、`dsh-remote-local-plugin`、`@njjpro/dsh-remote-workspace` 是"本地界面里直接操作远端会话"那一类，`dsh-remote-dsh` 是最轻量的"ssh -L + 整页接管"。

## 1. 先分清 "remote" 的两义（这是本调研最容易踩的坑）

| 含义 | 指什么 | 证据 |
|---|---|---|
| **官方 `ctx.remote.*`** | **前端调用宿主服务的 RPC 命名空间**，与"远程机器"无关。客户端组装挂载 12 个命名空间（`session` / `workspace` / `settings` / `credentials` / `llm` / `goals` / `agentPresets` / `commands` / `subagents` / `pluginInventory` / `messageFeedback` / `sessionReferences`），经 `/api/<namespace>.<method>` 一元 RPC 与 `/api/remote.mux` 单条多路复用 WebSocket 通信 | [dsh-in-depth · API 层：网关、Remotes 与控制器](https://dsh-in-depth.com/zh/llm-platform/apiproxy)（官方文档站，证据等级 A） |
| **社区插件里的 "remote"** | 真正的跨机器访问：SSH 远端工作区、隧道、局域网/公网入口、手机端 | 见下表（README 实测，证据等级 A/B） |

另外两个官方的**非**"远程"同名概念，别混：`dsh-remote-mock`（Typert Remote 流量的端点 mock，测试用）、`harness-relay-mcp`（给 Codex/Cursor 拉起 `dsh --profile codex` 的 MCP 适配层）。

## 2. 官方鉴权现状（决定"公司跑 dsh web + 家里浏览器直连"是否可行）

来自官方文档站点（证据等级 A）：

- 浏览器会话鉴权：宿主启动时铸造**按进程的 HMAC 启动令牌**，打印带 `?token=` 的 authenticated URL；浏览器打开该 URL 换得 `dsh-auth-<authority>` cookie（`HttpOnly; SameSite=Strict`，默认 30 天）后进入 `/api`；无有效 cookie 一律最小 401。
- 信任围栏：`isTrustedApiRequest` / `assertTrustedAuthority` 拒绝既非回环、又不在 `trustedHosts` 里的 `Host`（DNS rebinding 防御），即启动时须 `--trusted-host <你的域名:端口>`。
- **HEAD 已删除旧的 `PRIVILEGED_METHODS` 回环钉死清单** —— 注意：`dsh-lan-access` 的 README 里那段"设置页/凭据永远只有回环能访问、403"的说法基于**旧版本**，新版本已被 cookie 鉴权取代。

**推论**：「公司机器跑 `dsh web`，家里浏览器直连」这条路**官方层面是通的**，但要同时满足：① 网络可达（隧道 / VPN / Tailscale / SSH 转发）；② 用 `--trusted-host` 钉住访问域名；③ 用 `dsh web` 打印的 `?token=` URL 交换 cookie。**官方没有多用户账号体系**（没有用户名/密码、没有设备管理、没有撤销），这两块全靠插件补（`dsh-web-startup-auth` 补账号密码，`@linxin666/dsh-remote-web-ui` 补设备配对与撤销）。

## 6. 对用户场景的直接建议

- **只想要"在家里用公司那台 DSH 的会话和工作区"，两台都是自己的机器** → 首选 `dsh-ssh-workspace` + companion（本地界面集成，SSH 出站，远端不暴露端口），次选 `dsh-remote-local-plugin`（原生会话镜像，体验最像本地），前提是公司机器装的是 **DSH Desktop 0.2.1-rc.2/rc.3** 而不是别的版本。
- **只想最省事** → `dsh-remote-dsh`：公司机 `dsh web`，家里 `ssh -L 3081:127.0.0.1:3080`，侧栏点「远程」贴 token。三条硬约束记住：必须回环端口、token 每进程变、被控端要关掉一批"面向自己桌面"的功能。
- **公司在 NAT 内、家里也不方便 SSH** → 需要先解决"可达性"：Tailscale（多个插件一键检测/应用）或云隧道（`dsh-pocket` / `@linxin666/dsh-remote-web-ui` 都打包了 cloudflared）；再叠加 `dsh-web-startup-auth` 或 Cloudflare Access 补鉴权。
- **风险提示**：凡是"把 DSH 暴露到公网"的路线，等于把**本机命令执行能力**暴露出去；官方只有单进程 token，没有账号/设备/撤销体系。上线前至少加一道带账号的网关（`dsh-web-startup-auth`）或 Access JWT（`dsh-cloudflare-access`），并且优先选"隧道 + 回环"而不是"绑 0.0.0.0"。
