# 调研：DSH 官方的上下文机制（召回 / 压缩 / 其它）

> 快照日期：**2026-11-28** ｜ 本机 DSH **`0.2.2-rc.5`**（Desktop，asar）
> 数据来源：安装包内自带的 `docs/subsystems/*.zh.md` 与各包 `README.zh.md`（`C:\Users\Administrator\AppData\Local\Programs\DeepSeek Harness\resources\app.asar\dsh\...`）。
> 这些文档随版本发布，**对本机版本有权威性**；本文只在需要设计取舍处加「推断」。

## 0. 一句话结论

- **「上下文召回」不是一个内置功能名。** 0.2.2-rc.5 里被叫作「召回」的是三件不同的事：
  ① `ContextForm: 'recall'` —— **跨会话引用**（把别的会话的日志搬进来，搬的时候就裁）；
  ② **跨会话全文检索**（session-query + SQLite FTS5）；
  ③ **大输出落盘的读回**（spill 定位符）。
- **官方没有任何「从压缩结果里召回原文」的命令、工具或 API。** 压缩是单向的 `surfaceOp: replace`；但被遮蔽的事件**仍然在会话日志里**，只是从 `current` 表面挪到了 `shadowed` 表面。
- **官方压缩 = 替换 `compaction-basic` 的摘要式后端**：阈值触发 →（先可选确定性裁剪）→ 一次独立 LLM 调用生成八段式检查点 → 用一条 `user/message` 就地替换最旧的**平衡**范围。

## 1. 官方「上下文召回」

### 1.1 `recall` 只是一份「上下文形态」词表里的一个值

`MessageSource.form`（`ContextForm`）回答的是**这是什么东西**，与 `kind`（谁产出的）正交，共六个值：

| form | 含义 |
|---|---|
| `instructions` | 从工作区文件读出的、模型应当遵循的指令 |
| `catalog` | 本会话可用条目的目录（工具、技能…），变化时重新发布 |
| `snapshot` | 当前状态；同一生产者后一次快照顶替前一次 |
| `notice` | 刚发生的事的一次性告知，不顶替任何东西 |
| `relay` | 另一个 agent 发给本 agent 的消息 |
| **`recall`** | **从另一个会话的日志里取出、且可能在取出途中被削减的材料** |

出处：`docs/subsystems/llm-streaming.zh.md`（`ContextForm`）。

> 注意：`persistence-catalog.zh.md` 里还有一批生产者被登记为 `form: "recall"`（`action-cards`、`runtime-context`、`repeat-tool-reminder`、`schedule`、`model-selection`、`plan-mode`…）。它们是**同一形态的复用**（把已有材料重新搬进上下文），但语义上「跨会话搬运」这条由 `session-reference` 承担。

### 1.2 真正的机制：session-reference（跨会话引用）

包：`@deepseek-ai/dsh-session-reference`（服务 `ctx.sessionReferenceResolver`）。消费 `ctx.sessionQuery`，**不依赖** SQLite FTS。

**触发路径**：用户在提示词里写规范 mention `@[label](dsh-session:<base64url(id)>)`（或裸 `dsh-session:` URI）→ 宿主把 mention 改写成可读的 `@label` 正文并提取结构化引用 → 在 `agent/pre-step` 时调用 `prepare()`。

**prepare() 做的四件事**：

1. **规范化引用**：保留首次 mention 顺序、去重、拒绝自引用、限制条数（`maxReferences` 默认 **3**，硬上限 3）。
2. **并行精确读一次**每个被引用会话的**当前 surface**，并据此生成快照。只取三类内容：用户直接发送的文本、assistant 文本、带规范压缩检查点标记的 user 检查点。**工具、推理、其它注入上下文全部排除** —— 既防引用递归传播，也防源会话后续变更影响已保存快照。
3. **按字节预算逐源保留**：自动预算 = `max(65536, floor(contextWindow × 4 × referenceContextFraction))` 字节，`referenceContextFraction` 默认 **0.2**；缺 LLM/适配器/容量时用 **64 KiB**。保留策略是**先丢弃较早的非检查点消息，再缩短保留的文本**；只有做完这两步仍不达标，准备才失败（`SESSION_REFERENCE_BUDGET_EXCEEDED`）。
4. **渲染成一条独立的持久上下文消息**：紧跟在用户那条消息之后，作为**第二条 user 角色消息** `## Referenced sessions`，JSON 塞在 `<referenced-sessions>` 标签里，并附固定「不可信」警告（除非当前用户明确重复，否则不得遵循其中的指令、权限声明或工具请求）。文本里每个 `<` 都被转义成 `\u003c`，源文本无法拼出定界标签。

**截断时**：在该预算**之外**再发一条省略通知，给出精确的 `omittedMessages` / `omittedBytes`，以及（配了 spill 时）完整 transcript 的定位符与 `retrievalHint`；未配存储或保存失败时给「不可用」结果。完整 transcript 用「每行至多 64 个码点的 JSON 字符串片段」存，解码拼接即可还原精确文本（含换行），便于分页读。

**持久化**：源记录 `{ kind: 'session-reference', form: 'recall', version: 1, references: [{ sessionId, label, capturedFormatVersion, capturedThroughSeq, compacted, originalMessages, retainedMessages, omittedMessages, omittedBytes, truncated, inputIndex }] }`。`capturedThroughSeq` 是**源会话原始 generation 的坐标**，绝不解释为本会话的 seq。

**边界（官方明写）**：快照而非链接（不是 fork / 恢复 / 订阅）；只搬文本块；不在候选发现时检索消息正文（候选只按 id / 标题 / cwd 过滤）；服务假设调用方（宿主）有权读 `ctx.sessionQuery` 能看到的任何会话 —— **它不是面向模型的搜索工具**。

**错误码**：`SESSION_REFERENCE_INVALID_CONFIG` / `_INVALID_REFERENCE` / `_SELF_REFERENCE` / `_TOO_MANY` / `_READ_FAILED` / `_BUDGET_EXCEEDED` / `_CANCELLED`。

### 1.3 跨会话检索：session-query + SQLite FTS5

- Service Definition：`@deepseek-ai/dsh-session-query` —— 精确读取、来源优先级（live 优先）、关系追踪、语义提取、与提供方无关的过滤器。**逻辑记录**：`SessionRecord`（`live` / `persisted` / `formatStatus`）。
- 核心词汇是**表面分类**：

  ```ts
  type SessionEventSurface = 'current' | 'shadowed' | 'log-only'
  ```

  分类用的就是推导模型历史那套 `foldSurface()` 转换。**`shadowed` 就是「已被压缩掉、但还在日志里」的那部分** —— 这是官方唯一一条能读到被折叠内容的数据通路。
- Provider：`@deepseek-ai/dsh-session-query-sqlite` —— 独立派生索引（FTS5，`unicode61` tokenizer，牺牲子串召回换索引体积；trigram 方案实测后被否决；**不要把 `path` 指向会话持久化数据库**）。要字面子串扫描时用 `filterEvents()`。
- 面向模型的工具（`@deepseek-ai/dsh-tool-session-query`）：`session_event_read`（单事件全文 + 相邻概述，可带 `surfaces` 过滤）、`session_event_search`（字面全文，可按 `seq`/时间/`event_types`/`surfaces` 过滤）、`session_event_trace`、`session_search`、`session_trace`。

### 1.4 大输出落盘的读回：spill

`ctx.spillStore.saveText(input) → { locator, bytes, retrievalHint }` 是唯一操作：原样持久保存全文，返回不透明的模型可见句柄。本地后端写 `<root>/session-<sha256(sessionId)>/<random>-<safeName>`，根目录 0700、写入用 `open(path,'wx',0o600)` 防预植入符号链接。消费方是工具结果策略（`spill-policy`：超过 `maxInlineTokens` 的图文结果替换成「按原顺序保留的首尾 + spill 地址」，保存失败则保持内联，尽力而为）与会话引用（截断时保存完整 transcript）。官方打法是「给地址 + 提示用 read/grep 取回」，**不是**把内容塞回上下文。

### 1.5 「召回」的空白清单

| 想做的事 | 官方有没有 | 依据 |
|---|---|---|
| 把别的会话的上下文搬进来 | ✅ session-reference（有损、快照、不可信） | 1.2 |
| 在自己的历史里按词检索 | ✅ session-query（FTS5）+ 五个 `session_*` 工具 | 1.3 |
| 到磁盘上读回被落盘的大输出 | ✅ spill + 「用 read/grep 取」的提示 | 1.4 |
| **把压缩掉的段还原回上下文原位** | ❌ **没有命令、没有工具、没有 API** | 压缩只做 `replace`，见 §2 |
| 单独「召回」某条被遮蔽事件并让模型看到 | ❌ 只能自己读 `shadowed` 事件，再自己造一条消息 | 1.3 + §2.2 |

## 2. 官方的压缩（compaction）

### 2.1 三层结构

| 层 | 包 | 要点 |
|---|---|---|
| Service Definition（seam） | `@deepseek-ai/dsh-compaction` | `ctx.compaction`：`CompactionEngine` 抽象类。**每个 context 只能加载一个实现** |
| Service Provider | `@deepseek-ai/dsh-compaction-basic` | 拥有阈值、保留策略、事件排序、按路由的摘要调用、配置 |
| Consumer | `@deepseek-ai/dsh-command-compact` | 人类命令 `/compact` |

压缩**不属于 agent loop 主干**，是可选能力；缺 LLM / 会话存储 / token 测量时插件加载失败。

### 2.2 事务：三个只写日志的事件 + 一条 surface 替换

| 事件 | 载荷要点 | 作用 |
|---|---|---|
| `compaction/start` | `{ turn }` | 拿锁；数字=未结束的自动轮次，`null`=独立手动尝试 |
| `compaction/summary` | `summary`、`rawOutput`、`shadowedRange`（首尾 seq）、`shadowedSeqs`（surface 顺序）、`shadowedTokenCount`、`provider`/`model`/`maxTokens`/`usage`、`llmStreamCall` | 安全摘要投影 + 完整原始输出 + 被遮蔽节点清单；**只有带标记的记录才能证明走的哪条调用路径** |
| `compaction/end` | `{ turn, error? }` | 释放锁；`error` 记录失败尝试 |

三者都**只进日志、不进 surface**（不扩展 `SurfaceEventType`）。摘要本体承载在**另一条 `user/message`** 上，带 `surfaceOp: { op: 'replace', startSeq, endSeq }` —— 这是摘要压缩**唯一**的 surface 变更。

锁括住整个操作；中途崩溃表现为「有 start 无 end」的可检测遗留锁（同一生命周期内的遗留 start 会让入口点报 `busy`；`session/end-seed` 之前的遗留 start 是上一生命周期的陈旧证据，忽略）。手动路径只重新验证**所选位置 span** 稳定，所以摘要等待期间插入的空闲注入可以留在 start/end 之间。

**关键推论（对我们的设计）**：`compaction/summary` 保留了 `shadowedSeqs` 与完整 `rawOutput`，被遮蔽的事件本身也一直躺在 append-only 日志里。**「可逆」在数据层面本来就成立，官方缺的是「把它放回去」的原语与入口。**

### 2.3 三个入口 + 四个触发点

`CompactionEngine`：

- `compactIfNeeded(agent, trigger, signal)`，`trigger: 'pressure' | 'context-overflow'`
- `compactNow(agent, signal, sourceCommandId?)` —— 空闲会话强制缩一次（`/compact` 走这条），独立 `turn: null` 标记对，无有效范围时返回 `null` 且**不写任何东西**
- `compactRegion(start, end, agent, signal?)` —— 按 **surface 位置**（闭区间，非 seq 数值序）折显式区间

触发点：

1. **`agent/pre-step`**（自动主路径，串行）：为最新持久路由请求 envelope 定价，越过该路由阈值 → 先 prune，再摘要最旧的平衡范围。
2. **`agent/request`**：路由 listener 选定目标后、新 header 记入日志前检查压力（模型切换走这条）。
3. **`agent/request-error`**：提供方确认 `CONTEXT_WINDOW_EXCEEDED` → **绕过阈值与保留策略**，做一次最大平衡头部缩减；只有 surface replacement generation 前进才授权重试。
4. **`/compact`**：不走阈值。

### 2.4 选区与阈值（`compaction-basic` 的默认值）

设窗口 `W`、生效请求输出上限 `O`、余量 `B`：

```
触发阈值 = floor(min(W × thresholdRatio, W − O − headroomTokens))
保留预算 = (W − O) × retainRatio        // 逐字保留的近期尾部
```

| 配置 | 默认 | 含义 |
|---|---|---|
| `thresholdRatio` | `0.8` | 触发比例 |
| `headroomTokens` | `65536` | 输出预留之外的额外压力余量 |
| `retainRatio` | `0.16` | 逐字保留近期对话（与 `retainTokens` 互斥） |
| `maxTokens` | 跟随 `headroomTokens` | 摘要输出上限，含提供方计入的推理 token |
| `compactionRetries` | `1` | 压完仍高于阈值的额外尝试 |
| `maxOverflowRetries` | `1` | 确认溢出后的最大重试（`0` 只关恢复） |
| `summarizationProvider/Model` | `''` | 空对 → 最新已路由目标 → `AgentOptions` |
| `modelPolicies` | `[]` | 按 `{provider, model}` 覆盖上面全部字段 |
| `auto` | `true` | `false` 则只在手动时压 |

选区规则：

- **最旧的「平衡」范围**：切点必须保持 tool-call ↔ tool-result 配对（`toolPairingBalancedBefore/After`），区域边界**不要求保住整轮**（超大的轮里较早闭合的步骤也能被折）。
- 范围**永远从第一个不是 `system/message` 的节点开始** —— surface 第 0 号系统提示词永不被遮蔽。
- 保留近期尾部逐字不变；不可分单元（如一次巨型工具调用）拆不开，只能靠 pruner 削其文本主体。
- `compactRegion` **要求存在未结束的轮次**：在完全关闭的会话上手动调用会抛「no open turn」。

> 这条直接回答了上一轮调研留下的未验证项：**「surface 替换必须在开放轮次内」在 0.2.2-rc.5 上是官方文档写明的约束**（不只 CREMATOR 的 ISSUE-535）。

### 2.5 摘要调用长什么样

- 一次独立 `ctx.llm.stream()`，`GenerateOptions.purpose = 'compaction'`。
- **回放会话前缀**：surface 节点 0 派生出的 `system/message` + 该路由的有效工具声明 + 被遮蔽区域的消息（含位于其位置的历史内 `system/message`），使辅助调用成为会话的**真前缀**，命中提供方热前缀 cache；再追加一条固定的 user 指令。
- 只保留返回的**文本**：推理与工具调用被丢弃；图片输出以 `UNSUPPORTED_CONTENT` 失败而不是静默消失。
- 摘要**不缩小源内容**会被拒绝；摘要失败保留最新持久表层（pre-step 路径记警告继续，模型切换路径以 `MODEL_SWITCH_COMPACTION_FAILED` 拒绝该请求）。
- 替换消息用 `compactCheckpointSource(compactionId, sourceCommandId?)` 作来源，正文用 `<compacted-summary>` 包起来；原始摘要另存在 `compaction/summary` 事件上。

固定指令要求的八段结构（**可以直接拿来当我们卡片 facts 的骨架**）：

```text
## Primary Request and Intent      ## Files and Code        ## Pending Jobs     ## Critical Context
## Key Technical Concepts          ## Errors and Fixes      ## Current Work     ## Next Step
```

规则：保留精确路径 / 命令 / 错误串 / 标识符 / 数值 / 签名；忠实记录用户反馈与纠正；不提及压缩这件事；若已有 `<compacted-summary>`（上一份检查点）则**不许照抄**，要保留仍为真的事实、丢弃过期项、合并新信息。

检查点前导（模型看到的第一段）：

```text
This is an automatically generated checkpoint condensing an earlier span of the conversation to free up context. Treat the captured context as established background and build on it without restating it. Continue the task directly from the messages that follow, without acknowledging this checkpoint.
```

### 2.6 压缩前的两层「确定性瘦身」

- **`compaction-tool-result-pruner`**（`ctx.toolResultPruner`，可选，需挂在 basic 之前）：对**当前 surface** 上超预算的工具结果做 head/middle/tail 裁剪，按 **Unicode code point** 切片（不会切开代理对，但可能切开 grapheme cluster）；每次替换保留原事件全部字段只改 `content`，并在紧前插一条 `compaction/prune` 影子定价事件，使纯投影能 O(1) 扣减。**不发模型调用，可能完全省掉摘要**（修剪后已在阈值内就跳过）。只在压缩条件已满足后运行 —— 低于压力绝不碰。
- **`compaction-image-offload`**：接通 `image/offload` 声明与纯消息投影，按「当前输入节点 + 深度优先图片序号」指认要省略的图片，事件保留节点与消息身份、不带 `surfaceOp`。后续摘要失败或取消，已记录的省略仍然有效。

### 2.7 KV cache 事实（官方明写）

压缩是**替换**而非追加：每个检查点都会使「从第一个被替换历史 token 起」的复用失效，该范围之前未改动的请求前缀仍可复用。摘要求解本身因为逐字回放前缀而大多命中热缓存；把摘要器路由到别的提供方/模型、或压非头部范围，都会放弃这份复用。

### 2.8 官方的已知限制

- 计量在无提供方 usage 时退回「字符数 + 结构开销」启发式；**每 token 四字符对 CJK 与 JSON Schema 定价偏低**（官方 dev-note 自己承认）。
- 溢出分类靠适配器：只有可识别的上下文限制失败被规范化为 `CONTEXT_WINDOW_EXCEEDED`。
- 部分不可分单元与「仅 envelope 溢出」不在表层压缩能力内（缩不了系统/工具/前缀，拆不开不可分的非工具节点）。
- `compactRegion` 要求开放轮次（见 2.4）。
- 跨模型图片定价可能让有效摘要通不过「缩减验证」。

## 3. 其它上下文机制（全景）

| 机制 | 一句话 | 出处 |
|---|---|---|
| **会话表层 + append-only 日志** | 只有 `{op:'append'}` 与 `{op:'replace',startSeq,endSeq}` 两种 surface 变异；`deriveMessages()` 从日志折叠出模型历史；被替换的节点变 `shadowed`、非消息事件是 `log-only` | `session.zh.md` |
| **系统提示词组装** | 多个 `PromptSection`（静态或按组装期求值）按 order 拼成提示词；`PromptContext`（动态上下文）物化成**持久 user 快照**，只在完整快照变化或被压缩移除后重记。提示词本身是 surface 节点 0（`system/message`），之后变化走「原地替换」或 `systemPromptUpdate:'in-history'` 追加 | `system-prompt.zh.md` |
| **上下文形态词表** | `instructions` / `catalog` / `snapshot` / `notice` / `relay` / `recall`，纯语义、与呈现无关 | `llm-streaming.zh.md` |
| **Token 计量** | `ctx.tokenMeter.measure()` 按当前 surface 逐节点计价（O(surface)，可复用提供方 usage 锚点）；`contextPressure` 给 `pressureTokens` / `projectedTokens` / `contextWindow`；替换节点用与路由无关的 `heuristicTokens` 影子定价，保证 O(1) 投影折叠自洽 | `token-meter.zh.md` |
| **spill 大输出落盘** | 超 `maxInlineTokens` 的工具结果保留首尾 + 落盘地址；尽力而为 | `spill.zh.md` + `spill-policy` |
| **技能按需披露** | 会话前缀里只有 `catalog` 形态的技能摘要，模型调 `skill` 工具才把完整说明载入 | `skills.zh.md` |

## 4. 对我们「分层折叠 + 巡航 + 询问」设计的直接影响

1. **必须接管后端，不能并列**：`ctx.compaction` 每 context 只允许一个实现。要做「按 episode 折」就得**替换 `compaction-basic`**，自己拥有阈值、选区、摘要与事件顺序（seam 已把 `compactRegion` 留给我们）。
2. **展开只能自己做，官方不给原语**：没有「取消 replace」。所以
   - 展开 = 对**摘要节点**再做一次单节点 `replace(卡片节点, 卡片节点)`，正文换原文（就地还原，因果顺序不变）；
   - 再收起 = 同一原语的逆操作。
   数据来源不必自建归档：原事件一直在日志里，且 `session-query` 能把 `shadowed` 表面筛出来（见 §1.3）。自建 sha256 归档的价值是**校验与快照隔离**，不是「唯一副本」。
3. **官方主动给了两把尺子**：`projectedTokens`（下一次请求要花多少，专门为「压缩遮蔽后立刻反应」设计）算 headroom；`heuristicTokens`（与路由无关的影子价）用于替换节点的 O(1) 记账 —— 别自己估。
4. **八段摘要模板可以直接复用为卡片骨架**：`Files and Code` / `Errors and Fixes` / `Pending Jobs` / `Current Work` / `Next Step` 已经是我们想要的 `facts` 结构；官方规则「已有检查点不许照抄、只保留仍为真的事实」正好对应我们要的「父卡片由子卡片确定性合成」。
5. **「开放轮次」有了官方依据**：巡航不能起定时器随便折，必须挂在 `agent/pre-step` / 轮次闭合处；`compactRegion` 在已关闭会话上直接抛错。
6. **确定性瘦身是现成的第一层**：`toolResultPruner`（无模型、code point 精确、可能免掉摘要）已经存在，折叠层不该重复实现「削工具输出」；把预算花在「哪段该折」上。
7. **询问子 agent 的上下文天花板没变**：`spawn` 拿不到父对话、`fork` 只拿到「已完成轮次前缀」的快照，而折叠区在 surface 上已被遮蔽 —— 所以「向折叠区提问」仍然只能靠宿主喂原文（或给一支极窄读工具），这一点与上一轮设计稿结论一致，且现在有官方文档背书。
