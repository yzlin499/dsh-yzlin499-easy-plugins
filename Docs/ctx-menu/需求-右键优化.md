# 需求 —— 右键优化插件

> 状态：**需求收集中**（作者仍在补充，未定稿）。最后更新：2026-10-14。
> 本文件只记录需求与约束，不含设计。设计另开文档。
> 目标环境：DSH **0.2.0-rc.2** 桌面端（`DeepSeek Harness.exe` / Electron，Windows）。

## 一、已锁定的约束

| # | 约束 | 含义 |
| --- | --- | --- |
| C1 | **不得破坏外壳的「选中文本 → 复制」** | 该「复制」目前由 Electron 外壳提供（`lib/main.js` 里 `selectionText.length > 0` 分支）。右键插件必须在**没有自己的动作时完全不拦截**，命中才接管。 |
| C2 | **只做追加，不影响别的插件** | 不覆盖、不修改任何他人已注册的菜单项；命名空间化 id；优先往官方插槽追加，自绘只用于官方没有入口的地方。 |
| C3 | 交互形态：**传统分组菜单**起步 | 分组 + 图标 + 键盘 ↑↓/Enter/Esc；渲染层可替换（后续可能要换可搜索面板）。 |
| C4 | 定位：**先自己用，架构留出公开余地** | 首版不为通用性过度设计，但 API 形状与目录结构按可公开的分发规范做。 |
| C5 | 平台优先级：**桌面端为主（P0）** | 桌面端（Electron 窗口）是主战场；Web 端（浏览器打开 `127.0.0.1:19387`）**尽力而为（P1）**，不许为它牺牲桌面体验；**WSL 场景放弃**（不实现、不调研）。 |

> C5 的推导：桌面端才能用宿主侧能力（起进程、系统打开方式、原生文件管理器）。因此设计上允许
> 「桌面专属动作」存在，Web 端只做**优雅降级/隐藏**，而不是另做一套实现。

## 二、需求清单

### R1 —— 侧栏「工作区行 / 会话行」右键 = 直接弹出官方 ⋯ 菜单

**现象**（截图 1）：侧栏「工作区」区，工作区行 `dsh-yzlin499-easy-plugins` 需要先**悬停**才能看到 `⋯` 按钮，
点开才有两项菜单：**重命名**、**删除工作区**。会话行同理（每行一个 `⋯`）。

**期望**：在工作区行、每个会话行上**直接右键**即弹出同一个菜单（等价于点 `⋯`）。

**DSH 对应物**
- 会话行：官方 ⋯ 菜单已有插件插槽 `sidebar.workspaces.session.menu.item`（官方已占 `pin`100 / `rename`200 /
  `fork`300 / `archive`400），插槽注入 `useMenuOpenState` + `shortcuts`。
- 工作区行：**官方没有对应插槽**（社区实现靠 `__reactFiber$` 回溯 `ProjectRowItem` 的 props）。

**待调研**：右键能否**复用官方菜单组件与状态**（而不是自己重画一份）？会话行能否让官方菜单直接响应右键？

### R2 —— 聊天正文里的文件行右键（对齐 Codex）

**现象**（截图 2）：Codex 在聊天正文的「修改与验证记录」卡片里，对文件行右键弹出：

```
Open file
Open in Rider
Open with            ▸   VS Code / Default app / File Explorer / Terminal / WSL / Android Studio / Rider
Save as…
Copy path
Copy file contents
Open in Explorer
```

**期望**：DSH 对话正文里同类文件行（交付文件卡片 / 修改记录 / 文件引用）右键给出同等能力。

**DSH 对应物**（待确认）：`deliverables.file.actions` 插槽、`conversation.chat.turnTail`、
`workspaceChanges.summary/diff`、`workspaceFiles.*`、`session.openWorkspacePath({action:'reveal'})`、
`session.workspacePathApplications`。

### R3 —— 「修改完成后的审核」文件列表右键（对齐 Codex）

**现象**（截图 3）：Codex 的 `Edited 4 files / +171 −39` 审核卡片（含 Undo / View changes、每行 `+125 −27`），
对文件行右键弹出：

```
Open in Rider
Open with            ▸   （同上子菜单）
Save as…
Copy path
Copy file contents
Open in Explorer
```

**与 R2 的关系**：同一套文件动作菜单，只是**少了 `Open file`**。因此 R2/R3 应共用同一份动作表，
按上下文（是否可预览 / 是否属于本轮修改集）决定 `Open file` 是否出现。

**期望**：DSH 里「本轮改动的文件列表 / 交付文件卡片」的文件行右键给出同等能力。

## 三、动作清单（从截图提取，待作者确认取舍）

| 动作 | 图二 | 图三 | 备注 |
| --- | --- | --- | --- |
| Open file | ✅ | — | DSH 内预览 |
| Open in Rider | ✅ | ✅ | 编辑器直达（当前项目用 Rider/VS Code） |
| Open with ▸ | ✅ | ✅ | 子菜单：VS Code / Default app / File Explorer / Terminal / Android Studio / Rider（**WSL 已放弃**） |
| Save as… | ✅ | ✅ | 另存 |
| Copy path | ✅ | ✅ | |
| Copy file contents | ✅ | ✅ | |
| Open in Explorer | ✅ | ✅ | |

**注意**：子菜单里的 `Default app` / `File Explorer` / `Terminal` 是 Codex 在 **Windows** 上的
系统级入口，DSH 侧要用 `session.workspacePathApplications`（系统注册的打开方式）等能力重新映射。
`WSL` 按作者决定**不做**。

**平台标注（按 C5）**：`Copy path` / `Copy file contents` / `Open file` 预期纯客户端即可（桌面与 Web 都能用）；
`Open with ▸` 的动态应用列表、编辑器直达、`Terminal`、`Save as…` 预期依赖宿主侧能力（**桌面专属**，
Web 端隐藏或降级）——具体由 T2 调研确认。
