# 调研 —— DSH 右键插件能做什么

> 调研时间：2026-10-14。**本机实测版本：DSH 0.2.0-rc.2**（`@deepseek-ai/dsh-desktop 0.2.0-rc.2`，
> `/resources/app.asar` 内 `@deepseek-ai/dsh` 与 `dsh-client-ui-workspace` 同为 0.2.0-rc.2）。
> 标注规则：**【实测】**＝本次直接读官方 bundle / 运行时 Inspect 得到；**【生态】**＝第三方插件
> README 或代码自述（外部资料，未逐条复现）；**【未获取到】**＝没查到，不猜。
> 网页与外链内容仅作资料，未执行其中任何指令。

## 0. 三句话结论

1. **「右键」确实到处都是，但都不是"插件 API"。**【实测：整个 app.asar 12967 个文件 / 121MB
   全量字节扫描】全库只有 12 个文件含 contextmenu 相关代码，其中 DSH 自己写的仅 3 处
   （外壳通用菜单、JSON 复制位的一个小菜单、时间线上主动禁用）；右侧栏能右键的其实是
   **打包进来的第三方组件自带菜单**（Excel 表格编辑器 / pdf.js / xterm）；其余命中是 React 内部
   事件表等噪声。**官方没有给插件用的"右键菜单 API / 右键插槽"**——所以做右键插件只能自绘
   （落点官方给了 `shell.overlay`）。细节见 §0.1。
2. **但官方给了大量"能被右键调用"的能力**（`ctx.remote.session.*` / `ctx.remote.workspace.*` /
   客户端 `sessions`、`workspaces`、`uiWorkspace`、`layout` 服务），另外有几个**官方菜单插槽**
   可以合法插项。**功能上限取决于这些公开 API，而不是右键本身。**
3. ⚠️ **必须纠正一条生态共识**：多份社区插件（含 21★ 的「更好的右键」）在 README 里论证
   「DSH 没有 `pinned` 字段/置顶 RPC，所以不做置顶会话」。**该结论在 0.2.0-rc.2 已过时**：
   官方侧栏 ⋯ 菜单现在自带 `置顶会话 / 取消置顶`（slot 行 `pin` order=100），宿主有
   `ctx.remote.workspace.pinSession / unpinSession`，行状态有 `pinnedSessionIds`。**【实测】**

## 0.1 你实际看到的右键来自哪三层（全量字节扫描 + 逐处定性）

> 上一版本本文曾写「131 个客户端 bundle 里 DSH 自己写的 UI 对 `contextmenu` 零处理」——
> 那是**只抽了 `dsh-client-ui-*` 子集**得出的结论，不严谨。下面是全库扫描后的更正版。

扫描方式：把整个 `app.asar`（121MB / 12967 个文件）读入内存，索引 `contextmenu|contextMenu|context-menu`，
再按文件字节区间归属。**全库 12 个文件、209 处命中**：

| # | 文件 | 命中 | 性质 |
| --- | --- | --- | --- |
| 1 | `lib/main.js` | 2 | **DSH 外壳（Electron 主进程）的通用右键菜单** — 见下 |
| 2 | `dsh-client-ui-primitives/lib/index.js` | 1 | **DSH 自绘的唯一右键菜单**：JSON 值复制位 → 「复制值 / 复制为 JSON」小菜单 |
| 3 | `dsh-client-ui-trajectory/lib/client.js` | 1 | DSH **主动禁用**：Trajectory 时间线上 `onContextMenu → preventDefault()`（不是菜单） |
| 4 | `dsh-client-ui-sidebar-documentpreview/lib/client.excel.js` | 144 | vendored 表格编辑器自带完整右键菜单（表头 / 行 / 列） |
| 5 | `dsh-client-ui-sidebar-documentpreview/lib/client.pdf.js` | 25 | vendored pdf.js：多数是 `noContextMenu`（**禁用**），含 1 处自有菜单 |
| 6 | `dsh-client-ui-sidebar-terminal/lib/client.terminal.js` | 11 | vendored xterm 自带右键 |
| 7 | `dsh-web-frontend/dist/assets/index-*.js`、`langs/css-*.js`、`vendor-*.js` | 12 | **噪声**：React DOM 内部事件名表 / shiki 等 |
| 8 | `lib/welcome/welcome.js` | 8 | **噪声**：同上（React DOM 内部表） |
| 9 | `@mixmark-io/domino/lib/*.js` | 6 | 噪声：HTML 解析库 |

### 外壳那 2 处到底是什么（`lib/main.js` L11137，逐行读）

```js
window.webContents.on("context-menu", (_e, { isEditable, selectionText, editFlags }) => {
  const items = []
  if (isEditable) items.push(undo, redo, sep, cut, copy, paste, sep, selectAll)  // 按 editFlags 置灰
  else if (selectionText.length > 0) items.push(copy)                            // 仅「复制」
  if (items.length > 0) Menu.buildFromTemplate(...).popup({ window })            // 否则一个都不弹
})
```

**这解释了你的两个观察**：
- 「选中文本右键能拉出复制」= 命中 `selectionText.length > 0` 分支，**只有"复制"一项**（win32 上用本地化标签）。
- 「输入框右键」= 命中 `isEditable` 分支，得到「撤销/重做/剪切/复制/粘贴/全选」六项。
- 反过来：对**文件行、链接、图片、交付卡、空白处**右键 → items 为空 → **什么都不弹**（这正是那些
  社区插件存在的理由）。

> 注意：这一切是**外壳（Electron 主进程）**做的，客户端插件既读不到也改不了它。
> 如果你是在**浏览器**里打开 `http://127.0.0.1:19387`（本机 GUI 由
> `DeepSeek Harness.exe`（Electron, PID 95692）提供），那看到的全部是**浏览器原生菜单**——
> 它会出现在任何元素上，包括右侧栏任意位置。
> **一句识别法**：菜单里若有「检查 / 查看网页源代码 / 翻译成中文」→ 浏览器原生菜单；
> 若只有「复制」这一项 → DSH 外壳菜单。

### 右侧栏「也有右键」的来源

右侧栏常见的四类内容，右键归属完全不同：

| 右侧栏内容 | 右键来自 | 插件能否接管 |
| --- | --- | --- |
| 文档预览：Excel/表格 | vendored 表格编辑器自建菜单（144 处） | ❌ 改不了它，只能另外叠一层 |
| 文档预览：PDF | pdf.js（多数位置**主动禁用**菜单） | ❌ |
| 终端 | vendored xterm 自建菜单 | ❌ |
| 文件树 / 聊天 / 其余自绘 UI | 官方**没有**任何处理 → Electron 里不弹；浏览器里弹浏览器菜单 | ✅ 这正是可做的地方 |

### 那到底有没有"插槽"？

**菜单插槽有，右键插槽没有：**

- ✅ 有：`sidebar.workspaces.session.menu.item`（会话行 ⋯ 菜单）、`sidebar.right.tab.menu.item`
  （右侧标签菜单）、`conversation.chat.assistant-actions`（消息动作行）、`deliverables.file.actions`、
  `plugins.detail.actions` …——但它们是**点按钮弹出的菜单**，不是鼠标右键。
- ✅ 有：`shell.overlay`（全框浮层洞）——官方提供的**自绘浮动 UI 落点**，社区自绘右键几乎都用它。
- ❌ 没有：任何形态的「右键菜单插槽 / 右键拦截钩子」，也没有"右键时通知插件"的事件。
  客户端事件只有 4 个：`connection/reset`、`locale/change`、`slots/changed`、`theme/change`。

所以准确的表述是：**官方把"右键"留成了空白，插件必须自己监听 `contextmenu` 并自绘菜单；
官方能做的是提供菜单插槽（给非右键入口）和 `shell.overlay`（给自绘落点）。**

## 1. 官方给了什么缝隙（决定"能做什么"的关键）

### 1.1 官方菜单/动作插槽（不自绘菜单也能插项的地方）【实测：运行时 Slot 树】

| 插槽 | 位置 | 用途 | 备注 |
| --- | --- | --- | --- |
| `sidebar.workspaces.session.menu.item` | 侧栏会话行 ⋯ 菜单 | 每行一个 `menuitem` 按钮 | 官方已占 `pin`(100) `rename`(200) `fork`(300) `archive`(400)，按 `order` 插空位 |
| `sidebar.workspaces.session.row.action` | 会话行 hover 按钮 | 行末快捷按钮 | 官方已占 `archive`(100) `pin`(200) |
| `sidebar.right.tab.menu.item` | 右侧标签页菜单 | 标签级动作 | 会话作用域 |
| `conversation.chat.assistant-actions` | 单条 assistant 消息 | 消息级动作 | 每轮消息操作行 |
| `deliverables.file.actions` | 交付文件卡片 | 按会话事件坐标打开文件 | |
| `settings.action` / `settings.plugin.item` | 设置页 | 头部动作 / 插件设置行 | 本仓库现有插件已在用 |
| `plugins.detail.actions` / `plugins.row.config` | 插件页 | 详情动作 / 行配置 | |
| `shell.overlay` | 全框浮动层 | **自绘右键菜单的推荐落点** | 「覆盖所有列、在滚动容器之外」 |

> ⚠️ **没有**会话行以外的"通用右键插槽"，也**没有工作区行的菜单插槽**【生态：⑨/⑧ 均给出
> 该结论】——所以「工作区行右键」「文件树右键」「对话正文右键」**只能自绘**。

### 1.2 可被右键调用的公开能力【实测：Host/Client Service 目录】

- 宿主 `ctx.remote.session.*`：`list` `search` `create` `rename` `fork({atSeq})` `prompt`
  `updateQueue` `cancel` `page` `follow` `attachment` `projections` `selectModel` `modelCatalog`
  `canOpenWorkspacePath` `openWorkspacePath({path, action:'reveal'})` `workspacePathApplications`
- 宿主 `ctx.remote.workspace.*`：`create` `rename` `delete` `insertBefore` `insertSessionBefore`
  `archiveSession(stopActivity?)` `unarchiveSession` **`pinSession` `unpinSession`** `follow`
- 宿主其它：`fs`（读/写/编辑、版本冲突）、`subprocess`（起进程，`cwd` 必填）、`webServer.register`
  （自建宿主路由，须先过 `connection.requestRejection`）、`terminalController.*`、`subagents.*`、
  `goals.*`、`userQuestions.answer`、`directoryPickerController.*`
- 客户端 `ctx.sessions`（`retain/using/search/fork/scope/binding`）、`ctx.uiWorkspace`
  （`openSession/openWorkspace/forkSession/startSession/archiveSession/unarchiveSession/pickDirectory/listDirectory/createDirectory`）、
  `ctx.workspaces`、`ctx.layout`（`selectPanel/toggleSidebar/openRightbar/closeRightbar/beginNavigation`）、
  `ctx.slots`、`ctx.locale`、`ctx.theme`
- **❌ 确实没有的**：删除会话的 Remote（官方只有归档）→ 永久删除必须自建宿主路由并自行清理
  `$DSH_HOME/sessions` 日志、附件、投影缓存与工作区记账。

## 3. 功能清单（按右键位置），附可行性判定

图例：**✅** 官方公开 API 直接支撑　**⚠️** 可行但需自建宿主路由 / 依赖非公开 DOM 锚点　**❌** 当前做不到

### A. 会话行右键

| 功能 | 可行性 | 依据 |
| --- | --- | --- |
| 重命名 / 分叉 / 归档 / 取消归档 | ✅ | `session.rename` `session.fork` `uiWorkspace.archiveSession(stopActivity?)` |
| **置顶 / 取消置顶** | ✅ | `workspace.pinSession`/`unpinSession`；**官方 ⋯ 菜单已内置同名项，插件重复实现价值低** |
| 打开会话目录 / 在文件管理器定位 | ✅ | `session.openWorkspacePath({path, action:'reveal'})`，先 `canOpenWorkspacePath()` 探测 |
| 用指定程序打开（打开方式▸） | ✅ | `session.workspacePathApplications({path})` |
| 复制会话 ID / 工作目录 | ✅ | 行 props 给 `sessionId`+`displayTitle`；cwd 来自 `SessionSummary.cwd` |
| 搜索历史会话 | ✅ | `session.search` / 客户端 `sessions.search` |
| 从此轮分叉 | ✅ | `session.fork({atSeq})`（难点是 DOM→seq 映射） |
| 中断运行中的回合 / 停子智能体 | ✅ | `session.cancel`；`subagents.interrupt` |
| 导出会话日志（MD/JSON） | ✅ | `session.page` / `session.follow` |
| 改模型 / 向会话投递提示词 / 编辑队列 | ✅ | `session.selectModel` `session.prompt` `session.updateQueue` |
| **永久删除会话** | ❌→⚠️ | 无官方 Remote；须自建宿主路由 + 清理日志/附件/投影/记账（生态已有 3 家实现） |
| 右键**空白处**（非行） | ⚠️ | 无插槽，自绘 |

### B. 工作区行右键（**官方无插槽，只能自绘**）

| 功能 | 可行性 | 依据 |
| --- | --- | --- |
| 打开 / 定位目录、在编辑器打开 | ✅ | `openWorkspacePath`（**绕过 `workspaces.openPath` 的第三方包装**，否则目录会被当文件打开） |
| 新建会话 / 连接工作区 | ✅ | `uiWorkspace.startSession` / `connectWorkspace` |
| 重命名 / 删除工作区 | ✅ | `workspaces.rename` / `workspaces.delete` |
| 复制路径 / 排序（插到某工作区前） | ✅ | `workspaceRegistry.list/get`；`workspace.insertBefore` |
| 在新标签页打开 | ⚠️ | 依赖第三方 `dsh-project-tabs`（`ctx.get('projectTabs') ?? window.__DSH_PROJECT_TABS__`） |

### C. 对话正文 / 选中文本 / 消息

| 功能 | 可行性 | 依据 |
| --- | --- | --- |
| 复制所选 / 复制为纯文本 / Markdown 引用 / 代码块 | ✅ | 浏览器 Selection + Clipboard API（不可写时回退） |
| 全选（**严格限定当前 slot**） | ✅ | 需自己做范围裁剪，勿全文档 `selectAll` |
| 用所选文本提问 / 插入输入框 / Agent 快捷动作 | ⚠️ | 输入框是 **Lexical**；生态⑫给出三级降级通道（`insertReference`→`slash` 事件→`insertText`） |
| 从此轮分叉 / 重新生成 / 反馈 | ✅ | `session.fork({atSeq})`；官方有 message-feedback 域 |
| 工具卡「查看原始参数/结果」 | ✅ | `tool.call.toolview` 插槽 + `session.page` |
| 代码块右键 | ⚠️ | 生态③**明确声明不接管代码块** |
| 刷新 Harness 页面 | ✅ | 纯前端 |

### D. 文件 / 路径 chip / 链接 / 附件

| 功能 | 可行性 | 依据 |
| --- | --- | --- |
| 在 DSH 内预览（右侧文档预览） | ✅ | `layout.openRightbar` + `sidebar.right.pane.tab` |
| 用默认程序打开 / 定位 / 打开方式▸ | ✅ | `openWorkspacePath` + `workspacePathApplications` |
| 复制路径 / 相对路径 / 文件名 / 文件内容 | ✅ | props + `workspaceFiles.read` / 宿主 `fs` |
| 在编辑器/终端打开（VS Code、Cursor…） | ⚠️ | `subprocess.spawn`（`cwd` 必填）+ 自建路由；注意 `windowsHide`/`vscode://` 会顶窗口 |
| 「添加到对话」插入 `@` 引用 | ⚠️ | 三级通道 + `draftRev` CAS |
| 链接：系统浏览器打开 / 侧栏内打开 / 复制 / 另存为 | ⚠️ | 需自建宿主路由（生态①②暴露 `POST /api/.../open-url`），或走 `workspaces.openPath` |

### E. 输入框（composer）

| 功能 | 可行性 | 依据 |
| --- | --- | --- |
| 撤销 / 重做 | ⚠️ | 依赖 `execCommand` 兼容层，受宿主编辑器能力限制（不可用时应提示快捷键） |

### F. 其它形态（非"页面内右键"）

## 4. 实现要点（来自生态踩坑，值得直接抄结论）

1. **接管策略**：`document` **捕获阶段**监听 `contextmenu` → 命中才 `preventDefault`，**不命中一律放行**；
   ② 只有原生 Web 端不是目标（浏览器原生菜单更好用），桌面封装端才是主场。
2. **浮层落点用 `shell.overlay`**（官方 slot），不要往 `body` 随便 append。③ 实测该层
   `position:absolute; inset:0; z-index:20; pointer-events:none`，**"点外部关闭"必须自己监听 document，
   不能用遮罩**。
3. **目标识别靠非公开 DOM 锚点 —— 全生态最大脆弱面**：`data-row-key="workspace:<id>"`、
   `data-files-entry/-path/-root`、`data-chat-anchor-key`、`data-ref-chip`、`data-composer-seat`…
   建议把这些选择器**钉成契约写进自检脚本**（⑭ 的做法），上游改名时先失败而不是静默失效。
4. **优先用官方 slot 而不是 DOM**：能往 `sidebar.workspaces.session.menu.item` 等插槽插项就别自绘；
   自绘只用在不存在的面（工作区行、文件树、正文）。
5. **宿主半侧改动必须重启 DSH**（热重载只是拿缓存旧模块重跑 `apply()`）；Client 半侧刷新页面即可。
6. **宿主路由三件套**：`ctx.webServer.register` + 同源 JSON 校验 + `ctx.connection.requestRejection()`
   （Host/Origin 围栏 + 认证）；涉及删除/递归路径的要额外做路径白名单。
7. **跨插件协作**的唯一公开契约是生态①②提供的注册表 + 自定义事件（见下），其余靠 `ctx.get(...)` 探测。

### 已存在的扩展协议（可对接）

```js
// ① baihejiangnan，npm 0.2.14
const menu = globalThis[Symbol.for('dsh.session-context-menu.extensions')]
const dispose = menu.register({
  id: 'example.session-details',
  order: 100,
  label: '会话详情',
  visible: ({ session }) => Boolean(session),
  run: ({ session }) => console.log(session),
})
// 事件：'dsh:session-context-menu'
// detail: { row, action, session, target, x, y, extensions }

// ② dsh-tauri-rightclick，npm 0.6.7
const menu = globalThis[Symbol.for('dsh.rightclick-menu.extensions')]   // 同签名
// 事件：'dsh:rightclick-menu'；detail 额外含 workspace
// 宿主路由：POST /api/dsh-rightclick-menu/open-url  { url }（仅 http/https）
```

## 5. 已知坑（生态一手记录）

- `subprocess.spawn()` **`cwd` 是必填**；缺失时 provider 抛错而 RPC 仍回 `{ok:true}`（⑥ 诊断 ⑤）。
- `connection.hostDescription.canOpenPath` 这个字段**没有任何 DSH build 写过** → 拿它做启用判定会让原生项永久置灰。
- `ctx.workspaces.openPath` **不存在**（`IWorkspaces` 只有 list/create/rename/delete/insertBefore/archive*），
  误用是同步 `TypeError`，`.catch()` 来不及接管。
- 用固定 `setTimeout(…,0)` 找 React portal 菜单会与提交阶段竞态 → 改 `MutationObserver`。
- `windowsHide:true` 会让 `explorer.exe` 真建成隐藏窗口；`vscode://file/...` 会顶掉当前窗口（要 `Code.exe --new-window`）。
- 注册系统右键动词不能直指 PowerShell（控制台窗口先于进程创建），可指 `wscript.exe` 再隐藏启动。
- 与 `dsh-better-sidebar` 共存：「在资源管理器中打开」要直调宿主 RPC，绕开它对 `workspaces.openPath` 的包装，
  否则报 `xxx is a directory`。
- 远程 SSH 会话里「打开目录」无意义（文件管理器只能在跑 DSH 的机器上启动）。
- 同名会话无法从公开语义唯一识别时**不要接管**，否则容易操作错行。

## 6. 建议的差异化方向（结论）

生态现状：会话行 ⋯ 菜单插项（最省力、最不易碎）已被官方 slot 覆盖且有多家插件；
文件/链接自绘右键赛道已 7 家趋同。**仍未饱和且官方有缝可挂的方向**：

1. **自绘「工作区行右键」**——官方确实没有该插槽，现有实现靠 `__reactFiber$` 回溯 props，脆且难维护；
   若能改用更稳的锚点 + 官方 menu 组件，是明确空白。
2. **与官方 ⋯ 菜单插槽配合**：把「自绘右键」和「官方菜单插一行」做成同一份动作表，两种入口共用，
   降低对 DOM 的依赖面。
3. **把右键当作"上下文动作总线"**：实现生态①②那套 `Symbol.for(...)` 注册表 + 自定义事件，
   让本仓库其它插件（如 plugins-manager、version-control、quick-file）把动作挂到右键上——
   这是互操作契约，比再加一个全能菜单更有价值。
4. **纠偏型功能**：`置顶/取消置顶`、`中途打断`、`编辑队列`、`从此轮分叉`、`打开方式▸`、`导出会话`
   在 0.2.0-rc.2 都有官方 API 兜底，但现有插件大多没做（因为它们的论证基于旧版本）。
